2. LLM CALL BREAKDOWN BY TASK TYPE
================================================================================

COMPOSITION TASKS (Writing):
  - 1 execution call per atomic task
  - Optional 1 update call (update_diff=True)
  - Temperature: 0.3
  - Max tokens: 4096
  - Context: Previous article + dependencies + full plan

REASONING TASKS (Analysis):
  - 1 execution call per task
  - Optional 1 aggregation call
  - Temperature: 0.3
  - Uses: Full planning context + search results

RETRIEVAL TASKS (Search - Report Only):
  - 4 turns maximum
  - 1-2 LLM calls per turn (planning + merge)
  - Selector model: gpt-4o-mini (1 call per page)
  - Summarizer model: gpt-4o-mini (1 call per page)
  - Parallel workers: 8 (selector) + 8 (summarizer)
  - Total: 20-30 calls per search task

PLANNING TASKS:
  - Phase 1: 1 atom judgment call (determines if decomposition needed)
  - Phase 2: 1 planning call (generates DAG if complex)
  - Retry: Up to 10 retries per phase if parsing fails
  - Temperature: 0.1 (low variance)

3. RECURSIVE DECOMPOSITION MECHANISM
================================================================================

TWO-PHASE PLANNING APPROACH:

Phase 1: Atom Judgment (1 LLM call)
  - Input: Task goal + context
  - Output: "atomic" or "complex"
  - Determines if further decomposition is needed
  - Prompt: ReportAtom, StoryWritingNLWriteAtomEN, etc.

Phase 2: Recursive Planning (conditional, 1 LLM call)
  - Only triggered if Phase 1 returns "complex"
  - Input: Full planning context + task specifications
  - Output: JSON DAG with sub_tasks array
  - Recursively applies until all tasks are atomic
  - Prompt: ReportPlanning, StoryWritingNLPlanningEN, etc.

RECURSION LIMITS:

Story Mode:
  - No hardcoded depth limit
  - Naturally terminates when tasks become atomic
  - Typical depth: 3-4 levels

Report Mode:
  - force_atom_layer: 3 (line 454 in engine.py)
  - All tasks at layer >= 3 are forced atomic
  - Prevents unbounded recursion

Global Limit:
  - Max steps: 10,000 iterations
  - Practical limit: 3,000 steps (hardcoded abort at line 157)
  - Any run exceeding 3,000 steps terminates with error

TASK DECOMPOSITION GUIDELINES (from prompts):

  Rule 1: Last sub-task of writing task must be writing
  Rule 2: 3-5 sub-tasks per level (max 8, no more)
  Rule 3: Write tasks > 500-800 words (length guideline)
  Rule 4: Dependencies form DAG (no cycles)
  Rule 5: Flatten avoid over-planning (max branching)

EXAMPLE DECOMPOSITION (DeepSeek report):
  
  Level 0: Write "DeepSeek biography" (8,000 words)
    ├─ Level 1.1: Search "DeepSeek info" → 1 task
    ├─ Level 1.2: Think "Design structure" → 1 task  
    └─ Level 1.3: Write "Biography" (8,000 words)
         ├─ Level 2.1: Write "Founder background" (1,200 words)
         │    ├─ Level 3.1: Search "Liang Wenfeng background"
         │    ├─ Level 3.2: Search "Ubiquant AI technology"
         │    └─ Level 3.3: Write "Founder section"
         ├─ Level 2.2: Write "Company founding" (1,000 words)
         └─ Level 2.3-2.7: Similar structure
  
  Total: ~100-120 tasks for full biography

CACHE STRATEGY:

Caches Used:
  1. LLM cache (recursive/memory.py): llm.Cache()
     - Key: call_args_dict (model + messages hash)
     - Prevents duplicate identical calls
     - Invalidated on retry (overwrite_cache=True)

  2. Search cache: search.Cache()
     - Stores web search results

  3. Web page cache: web_page.Cache()
     - Stores downloaded webpage content

Cache Hit/Miss:
  - First attempt: Cache miss (full LLM call)
  - Retry (parse error): Cache miss (overwrite_cache=True)
  - Subsequent calls: Cache hit (no API call)

OUTPUT FILES:

Per Execution:
  - engine.log: Full execution trace (all steps)
  - nodes.json: Task graph (structure + results)
  - nodes.pkl: Pickled graph (for recovery)
  - memory.jsonl: Article + search results
  - report.md: Final report (markdown)

Logging Format:

10. RECOMMENDATIONS FOR OPTIMIZATION
================================================================================

TOKEN OPTIMIZATION:

1. Context Sampling
   - Truncate old dependency results beyond top 3
   - Sample context paragraphs (keep first + last 50%)
   - Could reduce input tokens by 30-40%

2. Prompt Template Optimization
   - Remove redundant instructions across prompts
   - Use shared instruction library
   - Could save 200-300 tokens per prompt

3. Model Selection
   - Use gpt-4o-mini for planning tasks (0.1 temperature)
   - Use gpt-4o only for writing (0.3 temperature)
   - Could reduce cost by 60%

4. Early Termination
   - Stop planning if plan is well-formed (no retries)
   - Terminate search after 2 turns if sufficient results
   - Could reduce calls by 20%

ARCHITECTURAL IMPROVEMENTS:

1. Token Budget System
   - Set hard limits per task type
   - Enforce context trimming if exceeded
   - Track budget usage per run

2. Analytics Dashboard
   - Real-time token tracking

   - Efficiency metrics per execution

3. Caching Enhancement
   - Cache planning results for similar tasks
   - Reuse atomic task outputs
   - Could prevent 10-15% of calls

4. Parallel Execution
   - Already parallelizes search (8 workers)
   - Could parallelize writing of independent tasks
   - Would reduce wall-clock time
